SRE Engine Architecture

The Swordigo Runtime Engine (SRE) is a native C11 guest library compiled for ARM64 (libsre.so) and mapped into guest memory at 0x2000000 alongside the original game engine (0x1000000).

SRE applies 16-byte ARM64 absolute function trampolines to intercept core game routines, bypassing legacy single-threaded CPU limits, mobile GLES immediate matrix calls, and GNU atomic string reference count locks.

// ARM64 16-Byte Absolute Trampoline Injection Sequence
LDR X16, [PC, #8]    // Load 64-bit target address from literal pool
BR  X16              // Branch to SRE replacement function in libsre.so
.quad 0x02001234     // Absolute 64-bit destination pointer

Platform Master Plan

SwordigoDesktop targets 100% platform independence across Linux x86_64, BSD, and handheld ARM64 Linux devices. The core compatibility layer maps Android Bionic libc and JNI OS calls directly into native host equivalents without relying on Android runtime daemons.

ARM64 JIT Correctness & Memory Audits

The JIT execution subsystem relies on Dynarmic, allocating a 512MB code cache buffer. Unsafe fast-path flags (Unsafe_UnfuseFMA and Unsafe_InaccurateNaN) are enabled to allow host x86 hardware vector units to execute NEON instructions directly.

LDXR/STXR Exclusive Locks Analysis

Under ARM64 emulation, atomic copy-on-write std::string refcount loops using LDXR/STXR instructions caused catastrophic thread spinlocks. SRE hooks replace these with single-threaded direct integer increment/decrement operations, completely eliminating the spinlock failure mode.

FBO Viewport Scaler & PostFX

Decouples internal game rendering (960x544) from desktop window dimensions. Implements multi-pass GLSL shaders for upscaling (AMD FSR 1.0, Sharp Bilinear) and post-processing (16-sample SSAO, 64-sample radial god rays, bloom extraction).

Swordigo Modding Guide & SwKiwi SDK

SwKiwi is the native modding framework supported by SRE. Mods define custom Lua scripts (`mini.toml` profiles) and hook engine variables directly through the Lua-Native Interface (LNI) without JNI overhead.
